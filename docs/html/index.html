SQUAD · DEDUVA — VENDOR-NEUTRAL, HUMAN-LED AGENT TEAMS

One team. Any model.
Every run on the record.

Squad — upstream, by Brady Gaster and contributors1 — gives you a human-led team of AI agents that lives in your repository as files: charters, routing, decisions, memory. This fork keeps the team and removes the landlord. The GitHub Copilot runtime it shipped on is gone, replaced by a typed provider seam that drives the same team with Anthropic or Gemini models, installs from a single bundled file, and can record every run to an ADP server as evidence a third party can verify.

It began as an exploration — what do multi-agent coding tools look like when no model vendor and no harness is load-bearing? The answer turned out to be an instrument. Once any model can drive the same team, differences become measurable; the first honest measurement showed the harness, not the model, moving the numbers — and that discovery became squad-lab, whose discipline became duva-bench.

01 · THE FORK

A team worth keeping, a platform worth questioning

Upstream Squad's design is the reason this fork exists at all: the team is state on disk, not a chat session. Each member has its own charter and history under .squad/; a coordinator routes work and — by explicit architectural rule — never does domain work itself; decisions land in a log; everything is inspectable in git. That is a genuinely good substrate for multi-agent engineering, and the fork changes none of it.

What upstream coupled it to was one platform: the README's badge reads Platform: GitHub Copilot, and the quick start is copilot --agent squad --yolo1. The fork's founding question was whether the team abstraction survives with the platform removed — model-agnostic, harness-agnostic, runnable where a vendor login or an open network is not on offer. It does, and the proof is mechanical: the whole decoupling is seven ordered commits you can step through below.

KEPT — UPSTREAM'S ARCHITECTURE, INTACT

Team-as-files state under .squad/ · a coordinator that routes and never implements · per-agent charters, histories, shared decisions · ceremonies and the Ralph watch loop · the CLI surface · the test suite, grown rather than forked away.

REPLACED — THE PLATFORM COUPLING

The @github/copilot-sdk transport → a typed backend seam (Anthropic · Gemini) · platform-provided execution → path-jailed workstation tools of Squad's own · server-side session resume → stateless backends · a 20-model catalog → an alias-only vendor registry · the @bradygaster/* npm scope → @deduvafork/*.

Two honesty notes. Parts of the docs tree still carry upstream's Copilot-branded text — the fork does not pretend otherwise, and upstream-sync is deliberately out of scope for the current milestone line. And attribution runs the right direction: the license is upstream's MIT, copyright Brady Gaster and contributors, and this page exists partly to say so.

02 · THE DECOUPLING

Seven commits to remove a platform

The fork was not drifted away from upstream — it was rebased onto v0.11.0 as an ordered seven-step replay, each step a commit that builds and tests, so the surgery is reviewable line by line. Play it through: what leaves, what replaces it, and what the test suite says at the end.

One step after the replay matters as much as the seven: the new workstation tools were wired into agent sessions only, never into the coordinator — "squad's own architecture is explicit that the coordinator routes work and never does domain work itself." Respecting the forked architecture more strictly than convenience suggested is what later made the fork usable as an instrument.

03 · ANY VENDOR, NO NETWORK

Neutrality as code, not configuration

Vendor neutrality fails quietly when it lives in documentation. Here it lives in types and tests: one registry module is the single source of truth for what a vendor is10, the backend loader map is typed over the provider union so registering a vendor without a backend is a compile error, and switching the default is one edit to DEFAULT_PROVIDER. Anthropic is the default today (premium / standard / fast tiers mapping to claude-opus-5 · claude-sonnet-5 · claude-haiku-4-5); Gemini sits behind the same seam.

ALIASES, NEVER PINS

The registry stores vendor aliases, never dated model pins — enforced by a registry-wide test, with a per-vendor pattern for what a pin looks like, because vendors disagree on what a version string is. Pinning happens where it belongs: in an experiment's arm spec, not in the product's defaults.

NO CROSS-VENDOR FALLBACK

Fallback chains stay on one vendor by rule: a session is bound to one backend, so "falling back" from Claude to Gemini would fail at the transport while looking like resilience in the config. A failure mode was deleted by making it unrepresentable.

AIR-GAP-FRIENDLY BY CONSTRUCTION

One esbuild file, an SDK with zero runtime dependencies, OpenTelemetry as optional dependencies that degrade to no-ops, an offline runtime path. The only network the team needs is the model endpoint itself. The bundling bug this bought — import.meta.url collapsing to the bundle path — was found, fixed, and changeset-documented.

04 · THE RECORD

Every run becomes evidence, or recording costs nothing

The fork is a working consumer of ADP5 on both of its planes at once. On the native plane, one assignment is one ADP run, each agent is a session, and every message, model call, tool execution and handoff crossing Squad's event bus is appended to a hash-chained trajectory. On the compatibility plane, Squad's unmodified gh-CLI adapter works against an ADP server as if it were GitHub — which is ADP's whole compatibility claim, and exercising it surfaced two real gh-usage bugs in Squad itself.

Recording is opt-in and honest about its own failure modes. Configuration names the token's environment variable and never writes the token; absent configuration, recording is off — and off must cost nothing. When it is on, three guarantees hold, and the one that makes trajectories evidence rather than logs is stepped through below.

NEVER BREAK THE THING YOU RECORD

Every recorder error routes to an onError hook and is swallowed. A telemetry layer that can fail the run it observes is an instrument contaminating its own measurement.

ATTESTED LABELS, NOT PARSED STRINGS

Vendor, model, tier and sdk_version are set when the run opens, immutable, and folded into the run's signed predicate — a cross-vendor comparison reads an attested field, never a filename convention.

A RUN CANNOT SCORE ITSELF

Runner and grader hold separate cryptographic identities; ADP marks each score separately_authorized by comparing them, and grader processes run with ADP tokens stripped from the environment.

05 · THE LAB

The comparison that wasn't one — and what it forced

squad-lab exists to run one goal across several providers and compare the results as evidence rather than as impressions. Its core framing is deliberately thin: an A/B test is one ADP intent and N ADP runs. The lab stores no scores, no token counts, no comparison table — only forward pointers, live process state, and the raw event log. Everything quotable lives in the attested record.

Its founding incident is the reason this whole line of work exists. An early three-model comparison produced a result that looked like a dramatic vendor gap — until the token accounting was read closely.

One backend ships its own Read / Write / Edit / Bash alongside Squad's registered tools; the other exposes only what Squad registers. And one backend silently caps sequential tool rounds at ten while the other ran to 105 tool calls — with the only trace a session:error nobody reads9. "That is not a model difference; it is two different programs." Every mechanism squad-lab added afterwards is that sentence, made structural:

harnessDigest() — "SAME HARNESS," CHECKABLE

A content digest over tool surface, system-prompt mode, harness implementation, charters, routing and limits — excluding the model by design. Results refuse to rank across mismatched digests, so the founding incident is now a banded warning instead of a publishable number.

AN 8-CLAUSE CONFORMANCE CONTRACT

Every harness implementation passes harness-check: completes a tool-using turn, stable ids, reports token usage and every tool call, quiescence on sendAndWait, a throwing tool fails the call not the turn, abort() works — and honours the tool-round budget, the clause the founding comparison broke silently. Budget exhaustion is a reported milestone, never a buried error.

ONE NEUTRAL LOOP

A second harness implementation runs every provider through one loop, one prompt, one tool schema, one stop condition (via the Vercel AI SDK), inheriting provider quirks knowingly — e.g. Gemini's thought_signature must be echoed back or degradation "looks exactly like a weaker model." The parity commit is its own done-condition: run the same model under both harnesses, and find no difference.

JOINABLE COUNTS, JAILED RUNS

One vendor reaches Squad's tools through MCP as mcp__squad__write_file, another as write_file — a prefix taxonomy makes counts joinable, and registered vs. built-in calls are reported separately, never folded. Every variant runs in a fresh clone with path-jailed tools.

And a set of reporting rules, each bought with a documented failure, that later graduated wholesale into duva-bench:

Rank per axis, never blended
One column per grader axis, ranked independently — no mean, no weighted score, no "overall." A composite is an editorial, not a measurement.
Unscored ≠ zero
A grader that exits non-zero leaves the run unscored. The fifth recurrence of one failure — "unknown" rendered as a number that means "free" — is why an unpriced model renders unpriced, never $0.00.
Graders are validated twice
Against a correct reference (must score 1.00) and a naive solution (must score lower, losing most on edge-cases). A grader that can't tell those apart doesn't measure anything.
The grader's hash is in the spec
Editing a grader mid-experiment moves the spec digest, and the summary declares the columns incomparable rather than quietly mixing rubrics.
Saturated tasks stay as controls
Two of six example tasks score near-perfect everywhere; they are kept and labelled as controls rather than deleted to flatter the instrument's sensitivity.
Five repeats buy a noise floor, not a p-value
The variance study computes pooled within-cell sd and contrasts in sd units — and explicitly declines to quote confidence intervals off five repeats.
06 · THE STATISTICS

Commitments made before the data — and a pilot that kept them

The lab's rules keep a comparison honest; statistics decide when a difference is real. The machinery is not bespoke: it is adp-replay's paired-statistics library6, pinned by commit in requirements-stats.txt — "two tracks whose numbers are meant to differ only by their data cannot float their statistics independently." Each practice below is enforced by code that fails, not by a paragraph asking people to be careful. Expand any of them.

A study spec — tasks, arms, repetitions, primary metric, exclusion rules — is validated, canonically serialized, and digested before execution. The digest is over the normalized value, not file bytes: reordering keys or switching YAML for JSON changes nothing; changing a model, toolset, docs grade, repetition count or grader changes everything. A task's identity includes its grader's sha256, because two studies that ran "the same task" under graders differing by a line are not comparable.

Amendments are permitted — "research that could never be amended would just be research that lies later" — but never invisibly: every amendment records the value it replaced, the pre-amendment reading stays computable, and reports print both. The pilot's report prints registeredDigest = currentDigest: registered and executed are the same object, provably.

Before any two arms are compared, the report states the pooled within-cell standard deviation per axis — how much the instrument wobbles when nothing varies. The pre-registered reading rule: a difference smaller than the pooled spread is not a finding, whatever its sign. The pilot's floors, verbatim from its report:

The fourth number is the discipline working: self-tests has a floor an order of magnitude above the others, so the axis was declared unreadable at this scale and excluded from interpretation — printed, not hidden.

Arms see the same tasks, so tests are paired: an exact McNemar over repetitions paired positionally within each task — the only pairing the design supports. Confidence intervals bootstrap over tasks, never trials (10,000 resamples, 95%, seed 0 — deterministic by construction): repetitions of one task are three looks at the same question, and resampling them as independent manufactures certainty the experiment never collected. A task only one arm ran is dropped, not imputed, and dropped_tasks is reported.

Families of comparisons get Holm–Bonferroni correction with enforced monotonicity — "an uncorrected family of comparisons is how a study reports an effect it did not have" — and ICC is printed beside every rate, because near zero it means the tasks are not discriminating and no number of them will settle anything. All of it binary-outcome by design: the grader's own passed boolean, never a threshold invented over a score the grader didn't declare.

A run whose ADP /verify is not ok renders ERROR — never pass, never fail, never zero — and repetition verdicts fold errors in against the majority, so a flaky arm cannot launder failures into a smaller n. Outcomes are re-read from ADP alone, deliberately ignoring what the scheduler observed locally: the local knowledge and the attested record are exactly the two things that must agree.

Exclusion rules are decided in advance, and there are exactly two: unverified runs, and provider quota exhaustion — pre-registered after an earlier milestone lost 8 of 10 runs on one model to rate limits, and including them inflated the pooled noise floor 14×. Exclusion counts are printed whether or not any fired; the pilot printed zero.

Until 2026-08-08, the analysis imported whatever adp-replay checkout happened to sit on one laptop — "the statistics behind a published number were whatever happened to be checked out," and no CI could run the path at all. The fix is structural: a project venv built from a one-line requirements file pinning adp-replay by commit, a stats_version field resolved from pip's own install metadata and stamped on every result — falling back to unknown, never to a guess — and a CI job that builds the venv and asserts real statistics through it.

Deliberately not folded into the study digest: re-analysing the same experiment does not make it a different experiment. "The pin travels with the answer instead of with the question."

The instrument these statistics serve is the semantic twin: a toolset whose names are isomorphic renames of the real one — the twin calls the original handler, so equivalence is by construction and property-tested. Twin names are length- and structure-matched (a systematically longer name would vary token count alongside familiarity), pronounceable non-words re-rolled against a common-word list, drawn from one seeded stream shared by every arm — a different seed per arm would confound documentation with which nonsense names were drawn — and stripped of informative descriptions, so documentation is the only varying channel. Then the whole apparatus was pointed at a real question, at deliberately small scale:

The pilot's most useful output is the metric that did not move. With a four-tool surface presented as a schema on every call, the model has no occasion to invent a name — a floor effect. Pre-registering that metric was a reasonable bet, and it was wrong; finding out cost $8.03 and an hour instead of being discovered inside the full study, and the remedy is re-registration, not a mid-flight amendment. The scale reduction is itself pre-registered — "it cannot support a claim about familiarity, and the write-up must not make one." Direction matched the hypothesis everywhere; nothing survives Holm correction; the write-up says exactly that11.

07 · THE STACK

Boring where it should be boring

One npm-workspaces monorepo, ESM throughout, Node ≥ 22.5, TypeScript 6, MIT. The choices worth defending are the refusals: a zero-dependency SDK, a no-build benchmark package, and statistics that live in the language their library was written in.

Working end to end at v0.12.0-preview: the full upstream team model driven by Anthropic (default) or Gemini behind one typed seam; path-jailed local execution; a single-file install; opt-in ADP recording with attested labels and drop detection; 6,880 tests passing. 08 · WHERE IT LEADS

Graduating the science out of the fork

duva-bench was built inside this fork with its exit visa stamped from day one: an import boundary enforced by a test that walks every import statement. The benchmark may consume only the fork's verified-separable modules — the event bus, the ADP client, the vendor registry — and SquadCoordinator is importable nowhere except the one arm that measures it. The rule was bought honestly: the coordinator turned out to answer benchmark-shaped messages itself — patterns like /^config\b/i matching ordinary task titles — producing empty trajectories that closed and looked normal. The trial runner removes it by construction rather than by vigilance.

The independent repo — github.com/DeDuva/duva-bench, Apache-2.0 — is not a relocation but a second track of the same experiment, built on open standards: Harbor, the container-per-trial harness behind Terminal-Bench 2.03, executing real agent CLIs; and ADP recording, so results verify identically on both tracks. Two tracks share tasks, graders, statistics and the attested record, and differ in exactly one layer — bespoke in-process execution here, mature in-distribution execution there. That is the fork's founding hypothesis applied to itself, and the cross-track prediction is registered in advance: same direction, larger magnitude on this track, because a one-turn arm that reaches for a missing tool has no second turn in which to recover. Whichever track wins, the loser's run is still evidence.

This page is the origin story; three projects carry the work forward. Each one stands alone, and each one is built to be checked rather than believed:

DUVA-BENCH →

Leaderboards got crowded. Answers didn't. Controlled factorial experiments over coding-agent arms — model × harness × toolset × task substrate — executed in Harbor containers, recorded as verifiable ADP trajectories, analyzed with pre-registered statistics. The question the fork surfaced, asked properly.

github.com/DeDuva/duva-bench
ADP →

Code got cheap. Trust didn't. An open protocol for making machine-written software trustworthy at machine speed: every change one signed record — intent → diff → evidence → provenance — admitted through a gate that tests the state that actually ships. The record layer everything on this page stands on.

github.com/DeDuva/adp
ADP-REPLAY →

Everyone has a number. Nobody can check one. Record an agent trajectory once, replay it under substituted models, and produce evidence-gated verdicts — fidelity and overhead gates, exact McNemar, task-level bootstrap. ADP's first consumer, and the statistics library this fork pins by commit.
