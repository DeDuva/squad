One team. Any model.
Every run on the record.

Squad — upstream, by Brady Gaster and contributors1 — is a team of AI agents that lives in your repository as files. This fork makes the team portable: swap Claude for Gemini, swap the harness, run one agent or a swarm, run it air-gapped. Nothing about the team changes.

Portability turned out to be the interesting part. Once you can swap any piece, you can measure any piece — and a measurement is only worth publishing if anyone can check it. So every run here closes into a signed record on ADP, verifiable by a third party with one call. This page is the story of how a fork became an instrument, and where the instrument led: squad-lab, then duva-bench.

01 · THE JOURNEY

From one platform to open standards, in six moves

Every project below exists because the one before it hit a wall worth understanding. Step through the whole arc in a minute — each stop says what changed and what carried forward.

Honesty notes, up front: parts of the docs tree still carry upstream's Copilot-branded text; both model backends are hosted APIs today, so "air-gapped" means no package registry, no telemetry export, and no network beyond the one model endpoint you point it at; and attribution runs the right direction — the license is upstream's MIT, and this page exists partly to say so.

03 · THE RECORD

Your forge remembers that code changed. ADP remembers everything that matters.

A git forge records diffs and who pushed them. It has no field for what a change was for, no proof it was verified against what actually shipped, and no record of which model, harness, and session produced it. That was fine while humans wrote slowly and reviewed everything. It breaks the day agents produce changes faster than anyone reads them — which is no longer a hypothetical day.

ADP is the substrate built for that world: every change and every run is one typed, signed record — intent → diff → evidence → provenance — and one endpoint, /verify, recomputes the proof on demand. GitHub and the new wave of agent-native infrastructure each solve a piece — storage, capture, speed. None binds evidence to what lands, and none lets a third party check. That's the uncontested layer, and it's the one ADP owns4.

This fork treats ADP the way applications treat a database: the lab and the bench store nothing ADP can answer. Reports are reconstructed from the attested record, never from local state — if our numbers and the record ever disagreed, the record wins, and you can query it yourself. Whether the future is one long-horizon agent or a swarm of thousands, the winning substrate is the one that can answer, per change and forever: what was this for, what ran against it, and what produced it. Diffs alone can't. The full argument — including how GitHub, Cursor, Entire, and the rest score against that bar — is on the ADP page.

04 · THE LESSONS

Why we stopped rolling our own

We didn't set out to learn infrastructure lessons — we set out to compare models. The comparisons kept teaching the same one: the layer you build yourself is the layer that lies to you. Here's the moment that lesson landed.

One harness quietly gave its model a second set of tools; another silently capped tool use at ten rounds while a third ran to 1057. Neither was a bug in a model — both were facts about our own plumbing, and both nearly became published "findings" about vendors. Each discovery became a control, and together they became a philosophy:

DISCOVERY 1 — THE HARNESS IS A TREATMENT

Not plumbing. If the loop, prompts, or tool surface differ between arms, you're comparing programs, not models. Now: every arm carries a content digest of its harness, and results refuse to compare across mismatches.

DISCOVERY 2 — SILENT LIMITS READ AS WEAK MODELS

A hidden ten-round cap looks exactly like a model that gave up. Now: an eight-clause conformance contract makes every harness prove the same behaviors — including honoring budgets out loud — before it's allowed in an experiment.

DISCOVERY 3 — EVERY BESPOKE LAYER IS A CONFOUND YOU MAINTAIN

The meta-lesson. Build only what differentiates — the science — and stand on best-of-breed for everything else: ADP for the record, the Vercel AI SDK for a neutral loop, and Harbor for execution at the standalone bench. Same model through our loop and the AI SDK's: no difference — that parity check is now a permanent regression test.

05 · THE SCIENCE

Commitments made before the data — and a pilot that kept them

Controls make a comparison fair; statistics decide when a difference is real. The machinery is adp-replay's paired-statistics library, pinned by commit so the numbers can't drift with someone's laptop. Each practice below is enforced by code that fails, not by a paragraph asking people to be careful. Expand what interests you.

A study spec — tasks, arms, repetitions, primary metric, exclusion rules — is digested before execution. Change a model, a toolset, or a grader by one line, and the digest changes; reorder keys or switch YAML for JSON, and it doesn't. Amendments are allowed but never invisible: the pre-amendment reading stays computable and reports print both. The pilot's report shows registered digest = executed digest — the study that ran is provably the study that was promised.

Before any two arms are compared, the report states how much the instrument wobbles when nothing varies — the pooled within-cell spread, per axis. The pilot's floors: acceptance 0.0216, api-shape 0.0000, edge-cases 0.0296 — and self-tests 0.3536, an order of magnitude noisier, so that axis was declared unreadable at this scale and excluded from interpretation. Printed, not hidden.

Arms see the same tasks, so tests are paired. Confidence intervals resample tasks, never trials: three repetitions of one task are three looks at the same question, and treating them as independent manufactures certainty the experiment never collected. Families of comparisons get Holm correction — an uncorrected family is how a study reports an effect it did not have — and every rate prints with its ICC, which says whether the tasks are discriminating at all.

A crashed grader leaves a trial unscored — never zero. An unpriced model renders unpriced — never $0.00. A run that fails /verify renders ERROR and counts against the majority, so a flaky arm can't launder failures into a smaller sample. The only exclusion rules are the two declared in advance — and the report prints their counts even when they're zero.

The statistics library is pinned to an exact commit, the resolved version is stamped on every result — falling back to unknown, never to a guess — and a CI job builds the environment from scratch and asserts real numbers through it. A study re-analysed months later gives the same answer, or says precisely why not. The pin travels with the answer instead of with the question.

A word on instruments, honestly ranked. The pilot used semantic twins — the real toolset under invented names, docs stripped, so documentation is the only thing that varies. Twins are the cheapest control and the weakest test: a frontier model can often see straight through an isomorphic rename, so whatever effect twins show is a floor, not a ceiling. The program's own conclusion is that the sharper instruments live further up the semantic-distance ladder — real but genuinely different substrates, think Python vs. Lua, or Flask vs. a framework the model has barely seen — where pattern-matching can't carry an agent home. That ladder is where duva-bench's language and framework studies go. The pilot's job was narrower: prove the machinery end to end, cheaply, and report whatever it found — including about its own metric:

The pilot's most useful output is the metric that did not move: with a four-tool surface presented as a schema on every call, a model has no occasion to invent a name — a floor effect. Pre-registering that metric was a reasonable bet, and it was wrong. Finding out cost $8.03 instead of a full study, the fix is re-registration rather than a mid-flight amendment, and the write-up says all of this in as many words9. Direction matched the hypothesis everywhere; nothing survives correction; no claim is made. That's what it looks like when the machinery is working.

06 · THE ECOSYSTEM

Born in the fork, built to leave

duva-bench grew up inside this repo with its exit visa stamped from day one: an import boundary enforced by a test, so the science never entangled itself with the product. The standalone duva-bench now runs on open standards — Harbor, the container-per-trial harness behind Terminal-Bench 2.02, executing real agent CLIs, with ADP as the record on both tracks. The fork keeps running as its in-process twin: same tasks, same graders, same statistics, differing in exactly one layer — execution. Whichever track wins, the loser's run is still evidence.

Three projects carry the work forward. Each stands alone, and each is built to be checked rather than believed:

DUVA-BENCH →

Leaderboards got crowded. Answers didn't. Controlled factorial experiments over coding-agent arms — model × harness × toolset × task substrate — executed in Harbor containers, recorded as verifiable ADP trajectories, analyzed with pre-registered statistics.

github.com/DeDuva/duva-bench
ADP →

Code got cheap. Trust didn't. An open protocol for making machine-written software trustworthy at machine speed: every change one signed record — intent → diff → evidence → provenance — admitted through a gate that tests the state that actually ships.

github.com/DeDuva/adp
ADP-REPLAY →

Everyone has a number. Nobody can check one. Record an agent trajectory once, replay it under substituted models, produce evidence-gated verdicts — fidelity and overhead gates, paired statistics. ADP's first consumer, and the statistics library this fork pins by commit.
